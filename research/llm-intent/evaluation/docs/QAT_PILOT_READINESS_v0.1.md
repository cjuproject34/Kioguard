# KioGuard QAT 파일럿 준비 기록 v0.1

기준일: 2026-10-01  
상태: **파일럿 준비 단계; QAT 학습·정확도 결과 없음**

## 현재 판정

Gemma4 E2B의 HF→GGUF 변환을 Colab 무료 T4 런타임에서 재시도했다. 10.28GB 스냅샷 다운로드는 성공했지만, `convert_hf_to_gguf.py --use-temp-file`가 58.51초 후 반환코드 `-9`로 종료됐다. 변환 중 관측된 RAM은 11.50/12.67GiB였고 GGUF 파일은 생성되지 않았다. 따라서 이 결과는 llama.cpp 비호환이나 Gemma4 품질 실패가 아니라 현재 host RAM 한계로 기록한다.

Qwen3.5 2B는 Q8_0·Q4_K_M PTQ와 20건 gate 채점까지 완료했다. 두 양자화 형식 모두 FP16과 같은 계약 유효율·완전 일치율을 보였지만 고영향 완전 일치율은 세 조건 모두 0%였다. 이 상태에서는 QAT가 필요하다고 단정하지 않고, 먼저 PTQ에서만 새로 생긴 회귀가 있는지 사례별로 분리한다.

## QAT 시작 조건

1. FP16과 PTQ의 동일 사례별 출력을 확보한다.
2. 오류를 `FP16 공통 오류`, `PTQ 유발 오류`, `transport/parser 오류`로 분류한다.
3. PTQ 유발 오류가 반복되고 안전 gate를 악화시키는 경우에만 QAT 파일럿을 연다.
4. 사람 검수가 끝난 승인 데이터와 독립 test를 분리한다. 현재 166건 초안은 동결 전이므로 학습 정답으로 사용하지 않는다.

## 이틀 일정에서 가능한 최소 파일럿

- 데이터 포맷과 train/dev/test 분할 검증
- 1개 모델·1개 양자화 목표에 대한 fake-quant/LoRA 학습 코드가 실제로 forward·backward·checkpoint 저장을 수행하는지 확인
- 5~20건 smoke로 adapter 병합·배포 형식 변환·계약 검증 경로 확인
- 정확도 회복, Android 성능 개선, 발열 개선은 측정 전 결론내리지 않음

## 보류 항목

- Gemma4 직접 PTQ/QAT: 12.67GiB보다 큰 host RAM 환경 필요
- 전체 가중치 QAT: 현재 Colab 무료 자원과 데이터 동결 상태에서는 완료를 보장할 수 없음
- S24 Ultra 성능·발열: 실제 단말 계측이 필요하며 Colab 결과로 대체하지 않음

## 다음 실행 순서

1. Qwen3.5 2B FP16·Q4·Q8 사례별 회귀표 작성
2. PTQ 유발 회귀가 있으면 해당 사례를 QAT 파일럿 검증 세트로 고정
3. 회귀가 없으면 QAT 대신 오류 원인(prompt/출력 계약/데이터) 개선을 우선
4. 별도 host RAM에서 Gemma4 변환을 재시도할 수 있을 때만 Gemma4 PTQ를 이어감
