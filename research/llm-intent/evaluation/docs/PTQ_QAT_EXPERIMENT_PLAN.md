# KioGuard PTQ·QAT 실험 계획 v1

기준일: 2026-09-28  
상태: **실험 전 계획. 아래 효과와 수치는 측정 결과가 아님**

## 시작 조건

PTQ는 FP16 공통 조건의 20문장 게이트와 118건 선택 평가를 통과한 1~2개 모델에만 수행한다. 현재 완료된 네 모델은 모두 위험 행동 gate 또는 의미 품질 기준을 통과하지 못했으므로 아직 양자화 주 후보가 확정되지 않았다. Gemma 4 E2B, Gemma 2 2B, TinyLlama gate를 마친 뒤 후보 여부를 판단한다.

## PTQ 우선 실험

동일한 원본 모델 revision과 동일한 tokenizer를 사용하고 변환 도구·명령·파일 hash를 기록한다. 모바일 배포 형식이 GGUF/llama.cpp로 확정되는 경우 다음 순서를 권장한다.

| 순서 | 형식 | 목적 | 판정 |
|---:|---|---|---|
| 0 | FP16 또는 BF16 기준 | 의미 품질 기준점 | 기존 공통 평가 보존 |
| 1 | Q8_0 | 작은 품질 손실에서 크기 감소 확인 | gate 실패 시 더 낮은 bit 중단 |
| 2 | Q6_K | 품질·크기 중간점 | Q8과 비교 |
| 3 | Q5_K_M | 모바일 후보 | 118건과 회귀 평가 |
| 4 | Q4_K_M | 경량 한계 확인 | 안전 gate와 슬롯 손실 집중 확인 |

모델 구조나 엔진이 해당 GGUF 형식을 지원하지 않으면 형식을 억지로 맞추지 않는다. 그 경우 ExecuTorch, ONNX Runtime, LiteRT 등 실제 Android 엔진이 지원하는 weight-only 정수 양자화를 별도 분기로 검토한다. 호환성은 변환 성공, 로드 성공, 20건 생성 성공으로 각각 기록한다.

PTQ마다 다음을 같은 조건으로 비교한다.

- 계약 유효율, 의도 순서 일치, target·slot·condition·dependency·fallback 일치
- 요청하지 않은 `CANCEL`, `COMMIT_REQUEST`, `RESET`과 `must_not` 위반
- 모델 파일 크기, 변환 시간, peak host RAM
- Colab 생성 시간은 참고값으로만 기록
- 최종 Android 실험을 하게 되면 S24 Ultra에서 cold/warm latency, peak RSS/PSS, 배터리와 온도 변화를 별도 측정

PTQ 채택 기준은 FP16 대비 허용 손실을 실험 전에 고정해야 한다. 현재 데이터가 `DRAFT`이고 네 모델이 gate를 통과하지 못했으므로 정확도 허용 폭을 숫자로 확정하지 않는다. 먼저 정답 검수와 후보 FP16 통과가 필요하다.

## QAT 파일럿

QAT는 PTQ에서 확인된 반복 오류가 양자화로 인한 것일 때만 실시한다. FP16에서도 틀리는 의도·슬롯 오류는 QAT가 해결한다고 가정하지 않는다.

1. PTQ 전후 동일 사례의 회귀를 비교해 양자화 유발 오류를 분리한다.
2. 전체 가중치 QAT 대신 지원되는 구조에서 LoRA/QLoRA 또는 fake-quant 기반 소규모 파일럿을 먼저 수행한다.
3. 학습·검증·독립 test를 분리하고, 현재 118건을 학습과 최종 평가에 동시에 사용하지 않는다.
4. seed, 학습 데이터 revision, adapter 설정, learning rate, epoch, checkpoint, peak VRAM을 기록한다.
5. adapter 병합 후 실제 배포 양자화 형식으로 다시 변환해 평가한다. 학습 체크포인트 점수만으로 채택하지 않는다.

무료 Colab T4와 이틀 일정에서는 전체 LLM QAT를 완료·검증하기 어렵다. 가능한 범위는 데이터·파이프라인 검증과 소규모 파일럿이다. QAT가 정확도를 회복할지는 실험 전에는 알 수 없다.

## 중단 조건

- 변환·로드·생성 중 재현 불가능한 오류가 반복됨
- 위험 행동 gate가 FP16보다 악화됨
- 계약은 유지되지만 target 또는 slots 오류가 뚜렷하게 증가함
- 파일 크기 절감에 비해 지연 또는 메모리 이점이 없음
- 실행 엔진이 Galaxy S24 Ultra의 실제 배포 경로와 호환되지 않음

## 산출물 규칙

각 실험은 새 디렉터리에 `run_manifest.json`, 원본 `predictions.jsonl`, v1/v2 score, 변환 로그, hash, 자원 측정을 저장한다. 기존 FP16·smoke·PTQ 결과는 덮어쓰지 않는다.
