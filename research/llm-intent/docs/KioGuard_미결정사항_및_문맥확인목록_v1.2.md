# KioGuard 미결정 사항·문맥 확인 목록 v1.2

기준 문서: [의도 정의 v1.2](KioGuard_의도정의_경계기준_v1.2.md)

## 1. 현재 상태

사용자께서 지정한 다섯 발화의 기준은 수정본에 반영했다. 더 이상 같은 뜻을 정해 달라고 요청할 항목이 아니다. **아직 결정되지 않은 음성 기능 두 가지**, **그 밖의 해석에 필요한 문맥**, **의도는 정해졌지만 실제 안내에 필요한 정보**를 아래처럼 구분한다.

이 목록의 항목들이 이번 문서 수정을 막는 것은 아니다. 최종 의도 수와 평가 시나리오를 확정하거나 실제 앱에서 안내할 때 처리할 항목이다. 파일·Drive·단말을 추가로 조사하거나 모델을 실행한 결과는 아니다.

## 2. 반영 완료: 다시 결정하지 않아도 되는 기준

| 발화 | 사용자가 정한 기준 | 반영 결과·적용 행 |
|---|---|---|
| 따뜻한 걸로 두 잔이요 | 선택한 상품의 옵션 | I02 설정, 온도=따뜻함·수량=2 · FD-03 |
| 처음으로 돌아가주세요 | 첫 화면 이동 | I07 NAVIGATE(HOME) · FD-22·GV-19 |
| 화면을 못 찾겠어요 | 정확히 어떤 화면인지 재질문 | ASK_SCREEN_TARGET · FD-24·GV-20 |
| 취소하고 다시 처음부터 할게요 | 현재까지 주문한 내역 취소 후 처음 화면으로 이동 | I08 CANCEL → I07 NAVIGATE(HOME) · FD-08 |
| 번호표 뽑는 거 알아요 | 재질문 | ASK_GUIDANCE_NEED · GV-09 |

원문·V1 정답은 [48발화 수정 검토표](KioGuard_48발화_수정검토표_v1.2.md)에 그대로 보존했다. 총 5개 표현이 중복 행을 포함해 7개 행에 적용된다.

## 3. 미결정 기능: 두 가지

### F-PENDING-01. 현재 화면을 새로 읽는 음성 명령

예: “현재 화면 읽어 주세요”, “이 화면에 뭐라고 쓰여 있나요?”

- **정해진 부분:** 앱에는 화면을 인식하고 음성으로 안내하는 목표가 있다. 기존 안내를 다시 재생하는 요청은 I11로 정의했다.
- **미정인 부분:** 사용자가 음성으로 새 화면 읽기를 직접 요청하도록 지원할지, 그리고 이를 독립 의도로 둘지다. 실제 화면 읽기 기능 전체를 할지 말지 새로 묻는 것은 아니다.
- **구분하는 이유:** 기존 문장 재생과 달리 새로운 화면 취득/OCR, 읽을 영역 선택, 민감정보 필터링이 필요할 수 있다.
- **결정에 필요한 내용:** 음성 명령 지원 여부, 읽을 범위(전체/선택 영역/현재 단계 핵심 항목), 민감정보 처리, 최신 화면 확보 실패 시 대응.
- **설계 권고:** 음성 명령으로 지원한다면 READ_SCREEN 같은 명시적 의도로 정의하고 기존 안내 반복과 구분한다. 아직 확정 코드나 15번째 의도로 등록하지 않았다.
- **현재 처리:** 범위 결정 대기로 관리한다. 현재 14개 평가 데이터에 억지로 UI_CONTROL을 붙이거나 확정된 범위 밖 요청으로 학습시키지 않는다.

### F-PENDING-02. 도움 세션을 종료하는 음성 명령

예: “이제 도움 그만 받을게요”, “키오가드 안내를 종료해 주세요”.

- **정해진 부분:** 음성 재생 중지는 I11로 정의했으며, 명시적 앱 중지 버튼은 즉시 처리하는 제어다.
- **미정인 부분:** 음성으로 도움 세션 전체를 종료하도록 지원할지와 종료 범위다.
- **구분하는 이유:** 말소리만 멈추기, 도움 세션 끝내기, 주문 취소, 과업 초기화는 서로 다른 결과를 만든다.
- **결정에 필요한 내용:** 음성 명령 지원 여부, 카메라·마이크 처리 중단, 세션 문맥/임시 자료 정리, 앱 화면 전환과 모델 자원 해제 시점.
- **설계 권고:** 지원한다면 END_ASSISTANCE 등으로 종료 범위를 명시한다. 외부 키오스크 주문 취소로 연결하지 않는다. 버튼만 지원한다면 평가 범위에 버튼 전용이라고 표시한다.
- **현재 처리:** 범위 결정 대기. I08 CANCEL이나 I14 RESET으로 임의 매핑하지 않는다.

두 기능을 독립 의도로 추가하면 전체 의도 수가 늘 수 있다. 따라서 현재 14개는 수정된 핵심 체계이지 최종 개수가 확정됐다는 의미는 아니다. 기능 지원 결정을 모델 성능 실험 결과로 대신하지 않는다.

## 4. 추가 문맥이 있어야 해석을 확정할 수 있는 사례

아래는 이번에 사용자가 이미 지정한 다섯 표현과 별개의 항목이다. 실제 시나리오를 만들 때 해당 문맥을 입력에 포함한다. 과거 화면을 확보할 수 없다면 ‘새로 설계한 문맥’이라고 표시한다.

| 사례 | 부족한 내용 | 문맥에 따른 해석 | 필요한 자료 또는 확인 방식 |
|---|---|---|---|
| FD-09 ‘그 커피 그거 뜨거운 걸로 하나요’ | 주문/질문 의사, 가리키는 커피, 직전 질문 | 한 잔 주문 요청인지 뜨거운 음료 제공 여부 문의인지 등이 갈림 | “뜨거운 커피를 주문하시려는 건가요, 뜨겁게 가능한지 물으신 건가요?”처럼 확인. 상품도 별도 특정 |
| FD-02·FD-11·FD-26·FD-28·GV-02·GV-04·GV-06·GV-08 | 신규 요청인지 기존 선택 수정 질문의 답인지 | 신규 요청은 I01, 확인된 변경 맥락은 I02 | 신규/변경 단계·현재 선택·직전 질문. 별표만 붙인 채 하나의 확정 gold로 사용하지 않음 |
| FD-14·FD-15·GV-11·GV-12 | 결제수단 선택 단계인지 최종 거래 확인 단계인지, 대기 질문의 종류 | 수단 선택은 I04. 최종 확인 응답이라면 그 질문의 거래·범위에 연결 | 현재 단계, 질문 내용·대상·유효성. 안내 동의를 결제 확정으로 바꾸지 않음 |

문맥을 추가해도 앱이 외부 결제나 신청을 자동 실행하는 것으로 범위를 확장하지 않는다. 표의 후보는 모든 상황에 대한 완전한 해석 목록이 아니라 현재 확인된 주요 경계다.

## 5. 의도·대응은 정해졌지만 실행 시 확인할 정보

이 항목은 **의도 정의를 다시 결정할 필요가 있다는 뜻이 아니다.** 현재 화면·상태에서 신뢰할 수 있게 얻을 수 있다면 먼저 읽고 검증한다. 모든 내용을 사용자에게 반복 질문하지 않는다. 정보가 없거나 충돌할 때 필요한 것만 묻는다.

| 대상 사례 | 이미 정해진 내용 | 남는 정보 | 확인 후 달라지는 것 |
|---|---|---|---|
| FD-03 | 선택 상품 옵션을 따뜻함·2잔으로 설정 | 선택 상품 ID, 적용 대상이 여러 개인지 | 어느 상품의 옵션을 안내할지 |
| FD-08 | 현재 주문 취소 후 첫 화면 이동 | 현재 주문 범위, 결제 전후 상태, 취소 가능 여부·결과 | 올바른 취소 안내와 이동 순서. 실패/미확인 시 다음 단계 보류 |
| FD-22·GV-19 | 첫 화면 이동 | 앱/키오스크의 어느 흐름인지, HOME 동작의 효과 | 이동 방법과 추가 효과 확인. 초기화 의도로 바꾸지 않음 |
| FD-24·GV-20 | 어떤 화면인지 재질문 | 사용자가 찾는 구체적 화면 | 답변을 받은 뒤 메뉴 안내/문제 지원 등 후속 의도 판단 |
| GV-09 | 안내를 원하는지 재질문 | 방법 안내가 필요한지 | 동의하면 방법 안내, 아니면 일방적으로 설명하지 않음 |
| GV-01·GV-03 | 서류 발급 요청 I01 | 필요한 서류 종류 | 실제 발급 메뉴 선택 안내 |
| FD-12·FD-25·FD-23·FD-27·GV-17 | 선택 또는 방법 문의 후보 | ‘그거/이거/이게’가 가리키는 실제 항목 | 상품/버튼 연결. 임의 대상 지정 방지 |
| FD-20·GV-16 | 글자 확대 I11 | KioGuard 글씨인지 외부 기기 글씨인지 | 앱 제어 또는 외부 설정 방법 안내. 외부 제어 완료 주장 금지 |
| FD-10·FD-16·GV-07·GV-15 | 지원/조건 질문 I10 | 실제 매장·기관·기기의 지원 근거 | 근거 있는 답변 또는 미확인 안내 |
| FD-18·GV-13 | 민감정보 입력 위치 문의 I09 | 실제 입력 화면·키패드 위치 | 올바른 위치 안내. PIN 실제 값은 수집하지 않음 |

## 6. 영향도·복잡도가 일부 잠정인 이유

사용자가 의도를 정해 주셨더라도 실제 상태와 안내 결과가 모두 정해진 것은 아니다. 첫 화면 이동은 동일한 I07이지만, 빈 화면에서 이동하는 경우와 중요한 입력이 사라지는 경우의 영향이 다르다. 선택 상품을 따뜻하게 바꾸는 단순 문장도 어떤 상품인지 화면에서 특정해야 한다.

따라서 48발화 표에서 U는 정보 부족을 유지하고, 복잡도는 원문 기반 잠정 등급으로 표시한다. 최종 평가 시나리오에 상태·효과·대상 연결을 포함한 뒤 등급을 확정한다. U를 L로 바꾸거나 잠정 C1을 근거로 Rule에 바로 통과시키지 않는다.

## 7. 현재 결정이 필요한 것과 다음 작업의 구분

제품 차원의 추가 결정은 3절의 음성 기능 두 가지다. 그 밖의 4~5절은 시나리오 작성 또는 실행 중 확보할 문맥이다. 사용자께서 이미 정해 주신 다섯 기준은 반영 완료했으며 재승인을 요구하지 않는다.

이번 작업에서 완료한 것은 의도 정의 수정, 기존 48행에 대한 수정 반영, 미결정·문맥 목록 분리다. 모델 실행·양자화·QAT·실기기 측정이나 새 기능 구현은 진행하지 않았다.
