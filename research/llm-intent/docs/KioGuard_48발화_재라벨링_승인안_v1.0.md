# KioGuard 기존 48발화 재라벨링 승인안

작성일: 2026-09-27 · v1.0 · **조건부 검토안, 확정 정답셋 아님**

정의 문서: [의도 정의·경계 기준 승인안](KioGuard_의도정의_경계기준_승인안_v1.0.md)

## 1. 자료와 표기

기존 정답 CSV에서 보존한 48행의 ID·발화문·V1 정답을 그대로 옮겼다. 대화에서 앞서 확인한 [Drive 정답 자료](https://drive.google.com/file/d/1N10Qfh3NN_WVdxdqVGXyw1ePFQ08kcLz/view)의 로컬 보존본을 사용했으며, 이번 작업에서 Drive 최신본을 재조회하지는 않았다.

새 의도·영향도·복잡도는 문서 검토 결과다. 모델 예측, 사람이 합의한 최종 라벨, 새로 측정한 성능이 아니다. 원자료에는 실제 화면·단계·직전 질문이 없으므로 아래 조건을 원래 실험 상황이었다고 해석하지 않는다.

- **의도 제안:** 현재 정의를 적용한 후보. 하나만 적혀 있어도 사람 검수가 필요하다.
- **별표(*)**: 독립적인 새 요청이라면 I01. 직전 변경 질문에 대한 답이었다면 I02 등으로 달라질 수 있어 원래 문맥이 필요하다.
- **보류:** 의도 목록 자체 또는 질문/진술 여부가 갈리는 사례. 이 상태에서 단일 라벨 정확도의 확정 gold로 쓰지 않는다.
- **영향도 U:** 문맥 미확정. `U→M/H`는 조건에 따른 후보 등급이지 H 실측이나 자동 H 할당이 아니다. 단순 선택·수정 단계는 보통 M 후보이며, 확인된 금전 확정·민감정보·중요 상태 소실 안내일 때 H를 적용한다.
- **복잡도:** 원문 의미 특성에 대한 제안. 대상·정보가 빠졌다는 이유만으로 CU를 부여하지 않는다. 실제 연산량을 측정한 값도 아니다.

| 4 | FD-20·GV-16 | 제어 대상이 앱인지 외부 기기인지 확인 가능한가? | I11 유지, 대상·직접 실행 가능 여부 분리 |
| 5 | FD-23·FD-24·FD-27·GV-17·GV-20 | 의도와 누락 대상을 각각 기록하는가? | GUIDE 유지 + 대상 확인 항목 |
| 6 | 결제·PIN·뒤로·처음 관련 행 | 실제 잘못된 안내의 영향과 단순 보호 키워드를 구분하는가? | 영향도 조건 확정, U를 L로 추정하지 않음 |

별표 행과 ‘보류’ 행만 문맥이 필요한 것은 아니다. 의도 후보가 명확해도 대부분의 다음 단계 안내에는 대상 화면·지원 정보·현재 단계가 필요하다.

## 5. 이 48행으로 아직 검증할 수 없는 부분

기존 48행에는 I06 BENEFIT_APPLY, I12 HELP, I13 PROCEED의 명확한 독립 사례가 부족하다. I08 CANCEL도 다른 목표와 분리된 사례가 부족하다. I11은 앱 제어 대상을 확정할 문맥이 없고, 범위 밖 요청·순수 부정·확인 응답·기술 오류·저영향 Rule 반례도 충분하지 않다. 이 자료만으로 14개 의도의 전체 정확도나 새 Router의 호출률을 대표할 수 없다.

다음은 **승인 후 새 평가 자료에서 보완할 예시**이며, 기존 48행이나 과거 점수에 합치지 않는다.

| 보완 대상 | 예시 | 기대 정답/행동 |
|---|---|---|
| 혜택 적용 | ‘이 쿠폰 적용해 주세요’ | I06 + 대상/적용 가능 조건 확인 |
| 특정 취소 | ‘장바구니의 라떼만 빼 주세요’ | I08 + 대상 범위 확인 |
| 일반 도움 | ‘직원에게 도움받고 싶어요’ | I12. 직원 호출 완료라고 허위 안내하지 않음 |
| 최종 진행 | 결제 확인 화면에서 ‘이 금액으로 결제 진행할게요’ | I13, 화면·금액·단계 확인. 외부 자동 결제 아님 |
| 저영향 제어 | KioGuard 안내 재생 중 ‘다시 읽어 주세요’ | I11, APP, L/C1 제안. Rule 허용은 별도 검증 |
| 부정만 있음 | ‘취소하지 마세요’ | 취소 금지 제약. 긍정 I08 실행 금지 |
| 확인 응답 | ‘포장할까요?’에 ‘네’ / 문맥 없이 ‘네’ | I03 확인 응답 / 대기 질문 확인 |
| 범위 밖·키워드 함정 | ‘생일 카드 문구 써 줘’ | 범위 밖. 결제수단 선택으로 오인 금지 |
| 근거 누락 | ‘현금 되나요?’ + 해당 기기 지원 정보 없음 | I10 + 근거 미확인. 질문 의도와 답변 가능 여부 분리 |

기존 48행은 정확히 같은 문자열 기준 38개 고유 발화이며, 띄어쓰기 변형까지 묶으면 더 줄어든다. 카페·관공서의 동일 문장을 다른 상황으로 평가하려면 실제로 제공하는 문맥의 차이를 명시해야 한다. 같은 문장이라는 사실을 숨기거나 단순 반복을 독립적인 일반화 사례로 계산하지 않는다.

## 6. 검수 상태

- 원문·V1 라벨·ID: 보존본 48행과 대조.
- 새 의도·영향도·복잡도: 이번 문서 제안, 사람 간 합의 전.
- 실제 화면·직전 질문: 이번 작업에서 복원하지 않음.
- 모델·Rule의 새 예측·정확도: 실행·측정하지 않음.
- 기존 문서·실험 원본: 수정하지 않음.

이 표를 검토한 뒤 정의에 동의하는 부분을 승인하고, 미확정 사례에는 문맥을 추가하거나 의도 미확정 상태를 유지한다. 신규 독립 평가셋과 PTQ/QAT 비교는 같은 정의가 고정된 이후에 진행한다.
